# Windows 效能監控 使用說明

適用版本：2.0.0（預覽版 2.0.0-rc.1 起）

Windows 效能監控會在本機持續記錄 CPU、記憶體、磁碟、NVIDIA GPU、網路、程序與 ACPI 熱區溫度，畫面即時顯示，
資料寫成 CSV 供 Excel 分析，並可產生離線 HTML 報告。資料只留在本機，不連線、不上傳。

> 視窗介面為深色主題（不提供切換）；離線 HTML 報告維持淺色，方便分享與列印。

## 1. 安裝與執行

1. **系統需求**：Windows 11 或 Windows 10 22H2（64 位元 x64）。不需要另外安裝 .NET，也不需要系統管理員權限。
2. **下載**：`WindowsPerformanceMonitor-<版本>-win-x64.zip`。
3. **核對檔案（建議）**：在下載資料夾開啟 PowerShell，執行下列命令，結果應與 Release 頁面或 `SHA256SUMS.txt` 的值相同。

   ```powershell
   Get-FileHash .\WindowsPerformanceMonitor-2.0.0-win-x64.zip -Algorithm SHA256
   ```

4. **解壓縮**到任何資料夾（例如 `D:\Tools\WindowsPerformanceMonitor`），裡面有：

   | 檔案 | 用途 |
   |---|---|
   | `PerformanceMonitor.exe` | 主程式（視窗介面） |
   | `PerformanceMonitor.Cli.exe` | 主控台程式（進階：無介面監控、產生報告、診斷） |
   | `使用說明.md` | 本文件 |
   | `settings.example.json` | 設定檔範例（一般不需要，設定可在程式的「設定」頁修改） |
   | `CHANGELOG.md`、`THIRD-PARTY-NOTICES.md` | 版本紀錄、第三方授權聲明 |

5. **執行** `PerformanceMonitor.exe`。程式**沒有數位簽章**，第一次執行時 Windows SmartScreen 可能顯示
   「Windows 已保護您的電腦」：按「**其他資訊**」→「**仍要執行**」。第一次啟動會把元件解壓縮到暫存資料夾，稍慢屬正常。

**移除**：關閉程式後刪除解壓縮的資料夾；若也不要保留監控資料，刪除 `%LOCALAPPDATA%\WindowsPerformanceMonitor`。

## 2. 畫面

開啟程式即自動開始監控；上方顯示監控狀態與「開始」「停止」按鈕（Alt+S／Alt+T）。**關閉視窗即停止監控並結束程式**
（停止時會補寫最後一筆資料），沒有系統匣常駐。

| 頁面 | 內容 |
|---|---|
| 總覽 | 各項目目前狀態與數值、進行中的告警、最後取樣時間；各卡片下方有最近 5 分鐘的迷你走勢（CPU、記憶體、磁碟 I/O、GPU、網路、溫度） |
| 即時趨勢 | 最近 5 分鐘的折線圖：CPU 與記憶體、網路合計、各磁碟忙碌率、GPU 使用率與溫度。橫軸每分鐘一格；滑鼠移到圖上會顯示該時間各線的數值；CPU 與記憶體圖以紅色虛線標出告警門檻（告警停用時不顯示） |
| 磁碟 | 各磁碟容量；邏輯／實體磁碟的讀寫速度、IOPS、延遲、忙碌率；上方有讀取、寫入速度與忙碌率的 5 分鐘趨勢圖；容量的使用率有橫條，刻線為告警門檻，達告警條件時變紅 |
| 網路 | 納入統計的網路卡與下載／上傳速度、合計；上方有各網路卡下載、上傳的 5 分鐘趨勢圖 |
| 溫度 | NVIDIA GPU 溫度與 ACPI 熱區溫度；上方有 GPU 與 ACPI 熱區的 5 分鐘趨勢圖 |
| 程序 | 使用記憶體（Working Set）最多的前 N 個程序；Working Set 有橫條，長度相對於最大的程序 |
| 報告 | 選擇期間產生 HTML 報告（見第 5 節） |
| 狀態與錯誤 | 啟動檢查、CSV 寫入統計、各項目狀態與錯誤原因、最近告警事件 |
| 設定 | 所有設定（見第 3 節） |

**狀態**：正常（OK）綠色；暖機中（WarmingUp，第一次取樣）與停止中黃色；無法使用（Unavailable）與停用（Disabled）灰色；
錯誤（Error）紅色。無法取得的數值顯示「—」，不會以 0 代替。

**常見的「無法使用」**（不是故障）：

- **GPU**：只支援 NVIDIA 顯示卡，且需安裝 NVIDIA 驅動程式（含 `nvidia-smi`）。AMD／Intel 顯示卡顯示無法使用。
- **ACPI 熱區**：許多桌上型電腦沒有熱區，顯示無法使用。**ACPI 熱區不是 CPU 核心溫度**，部分電腦會一直回報固定值。
- **網路**：預設只統計實體網路卡（排除虛擬、VPN、Hyper-V 等）。要納入其他網卡，在「設定 → 網路介面卡篩選」的
  「納入名稱」填入網卡名稱（可用 `*`、`?` 萬用字元）。

## 3. 設定

在「設定」頁修改後按「**儲存並重新啟動**」：程式會檢查所有欄位，有錯誤時列出原因且不儲存；通過後寫入設定檔
（舊檔另存為 `settings.json.bak`），停止監控並自動重新啟動套用。「復原」回到目前使用中的設定，「填入預設值」載入內建預設值（尚未儲存）。

| 分區 | 主要欄位（預設值） |
|---|---|
| 監控週期 | 畫面更新 2 秒、取樣 2 秒、CSV 紀錄 10 秒 |
| 監控項目 | CPU、記憶體、磁碟容量、磁碟 I/O、GPU、網路、程序、ACPI 熱區是否啟用 |
| 網路介面卡篩選 | 只統計實體網卡、納入名稱、排除名稱、合計只計納入的網卡 |
| 程序 | 前 N 名（5，1～20）、是否記錄到 CSV、記錄間隔（10 秒） |
| 告警門檻 | CPU 90%／恢復 85%；記憶體 90%／恢復 85%；磁碟可用空間 10%／恢復 12%（可加 GB 條件與 any／all） |
| 告警時間 | 持續 10 秒才告警、冷卻 60 秒、恢復需持續 10 秒、冷卻後是否再次通知 |
| 資料紀錄與逾時 | 是否寫 CSV、資料與 Log 目錄、檔案被鎖定時的重試次數、nvidia-smi 逾時 |

設定檔位置：`%LOCALAPPDATA%\WindowsPerformanceMonitor\settings.json`（不存在時使用內建預設值；欄位說明見 `settings.example.json`）。
設定檔有錯誤時程式仍會開啟，並在上方提示原因，但不開始監控。

## 4. 告警

CPU、記憶體、各磁碟可用空間達到門檻並**持續**設定的秒數後告警；在總覽頁與狀態頁顯示，並寫入 Application Log。
告警後進入冷卻，期間不重複通知；數值回到恢復值以下（磁碟為以上）並持續設定秒數後顯示「已恢復」。
告警只是提示，不會結束程序、刪除檔案或變更系統設定。

## 5. 報告

在「報告」頁選擇起日與訖日（或按「今天」「昨天」「最近 7 天」「最近 30 天」），按「**產生報告**」。報告在背景產生
（監控照常），完成後以預設瀏覽器開啟。報告是單一 HTML 檔，離線即可開啟，可直接寄送或列印。

報告內容：

- **統計摘要**：各項目的平均、最大、P95（95% 的時間低於此值），只計入正常取得的資料。
- **趨勢圖**：期間在 1 天以內每分鐘、7 天以內每 10 分鐘、30 天以內每小時、更長每日一點；實線為平均、淡色線為最大；
  程式沒有開啟的時段不連線。滑鼠停在圖上可看該時段的數值。
- **尖峰時段**、**告警事件**、**高記憶體程序**。
- **資料品質**：實際與預期紀錄筆數、缺失比例、監控時段、各項目不可用比例、缺少或損毀的檔案。

報告存在 `%LOCALAPPDATA%\WindowsPerformanceMonitor\Reports`（同一期間重新產生會覆蓋）；可按「開啟資料夾」。
一次最長 366 天。報告不會修改原始 CSV 與 Log。

## 6. 資料位置與備份

| 資料 | 位置（`%LOCALAPPDATA%\WindowsPerformanceMonitor\` 之下） |
|---|---|
| 設定檔 | `settings.json`（與 `.bak`） |
| 監控資料 CSV | `Data\<類型>_v1_YYYYMMDD.csv`，每天一個檔（本機日期），UTF-8 BOM，Excel 可直接開啟 |
| Log | `Logs\Application_YYYYMMDD.log`（啟動、停止、告警）、`Logs\Error_YYYYMMDD.log`（錯誤與不可用） |
| 報告 | `Reports\Report_起日-訖日.html` |

- 程式不會自動刪除舊資料；需要時自行刪除或備份 `Data`、`Logs` 資料夾。
- CSV 欄位說明見 GitHub 上的 `docs/Data-Schema.md`。CSV 中無法取得的數值是空白，並以 Status 欄說明原因。
- **隱私**：程序名稱可能透露你使用的軟體；資料只存在本機，分享前請自行檢查。

## 7. 主控台程式（進階）

在解壓縮的資料夾開啟 PowerShell：

| 命令 | 用途 |
|---|---|
| `.\PerformanceMonitor.Cli.exe --once` | 取樣一次並寫入 CSV 與 Log（`--once --json` 以 JSON 輸出） |
| `.\PerformanceMonitor.Cli.exe run` | 無介面連續監控，Ctrl+C 停止；`run --minutes 60` 60 分鐘後自動停止 |
| `.\PerformanceMonitor.Cli.exe report --from 2026-11-01 --to 2026-11-07` | 產生報告（`--out 路徑` 指定輸出位置） |
| `.\PerformanceMonitor.Cli.exe --self-check`、`--version`、`--help` | 自我檢查、版本、說明 |

主控台與視窗程式共用同一個設定檔與資料資料夾；**請不要同時執行兩者的監控**（會各寫一份資料）。
環境變數 `PERFORMANCEMONITOR_ROOT` 可改用其他資料根目錄（測試用）。

## 8. 常見問題

| 問題 | 說明 |
|---|---|
| 開啟時被 SmartScreen 擋下 | 程式沒有數位簽章。核對 SHA-256 後按「其他資訊」→「仍要執行」 |
| 上方紅色提示「設定或資料目錄有錯誤」 | 依提示修正設定（設定頁或 `settings.json`），或確認資料目錄可寫入 |
| GPU 或 ACPI 熱區顯示無法使用 | 見第 2 節；非 NVIDIA 顯示卡、沒有熱區的電腦屬正常 |
| 網路顯示無法使用或合計是 0 | 預設只計實體網卡；在設定加入「納入名稱」 |
| CPU 數值與工作管理員略有差異 | 取樣時間點與計算方式不同，短時間差異屬正常 |
| 工作管理員中程式的記憶體約 50～100 MB | 正常範圍；.NET 會在需要時回收記憶體 |
| 報告的缺失比例不是 0 | 每次監控的預期筆數可能 ±1 筆；系統休眠、電腦負載過重也會造成缺漏，詳見報告「資料品質」 |
| 想看錯誤原因 | 「狀態與錯誤」頁，或 `Logs\Error_YYYYMMDD.log` |
