# 0008：歷史分析與 HTML 報告

- 狀態：已採用
- 日期：2026-11-16（Phase 4 開工前，負責人確認全部照建議）

## 背景

開發規劃 v2.1 §8 要求讀取新版 CSV 與 Log、輸出單一離線 HTML，內容含平均／最大／P95、尖峰時段、趨勢、告警事件、高記憶體程序與資料品質；需決定產生入口、統計資料來源、尖峰時段定義、圖表做法、輸出位置、期間上限與損毀資料處理。

## 決定

| 事項 | 決定 |
|---|---|
| PR 拆法 | 4a：讀取 CSV／Log、統計、資料品質、主控台 `report` 命令（基本 HTML）；4b：HTML 內嵌 SVG 趨勢圖、尖峰時段、告警事件、程序統計；4c：WPF「報告」頁 |
| 產生入口 | 主控台 `report --from --to [--out]`（CI Smoke Test 實際產生並檢查）與 WPF 報告頁（選日期 → 產生 → 以預設瀏覽器開啟） |
| 期間 | 本機日期、含頭含尾，對應每日分檔；最長 366 天 |
| 輸出位置 | 預設 `<資料根目錄>\Reports\Report_YYYYMMDD-YYYYMMDD.html`，同名檔覆蓋；主控台可用 `--out` 指定 |
| 統計來源 | 平均、最大、P95 由 **CSV 原始紀錄**（每 `monitor.logSeconds` 秒一筆）計算，報告註明；P95 採 Nearest Rank。只計入狀態 OK 且有數值的紀錄，並列出有效／總筆數 |
| 趨勢粒度 | 照規劃表：1 天以內每分鐘、7 天以內每 10 分鐘、30 天以內每小時、超過 30 天每日；每段保留平均與最大，沒有資料的段斷開 |
| 尖峰時段（4b） | CPU、記憶體、磁碟忙碌（各段最忙的邏輯磁碟並標示）、網路合計下載、網路合計上傳、GPU 使用率（各段最高的 GPU）共 6 項，依趨勢粒度分段；依段平均由高到低檢視，與已選時段相鄰的段併入，其餘成為新時段，直到 5 個時段；沒有資料的指標不列 |
| 圖表（4b） | 內嵌 SVG，**不使用 JavaScript**；6 張：CPU、記憶體、各邏輯磁碟忙碌率、網路合計下載／上傳、各 GPU 使用率、GPU 溫度與 ACPI 熱區。每段平均為實線、每段最大為淡色線，沒有資料的段斷開；滑鼠停留以 SVG `<title>` 顯示該段數值；沒有資料的圖只顯示原因 |
| 告警事件（4b） | 依對象摘要：告警次數、再次通知次數、告警總時間（告警到已恢復；沒有恢復紀錄時算到該次監控結束並標示）、最後一次告警時的數值；明細列出最近 200 筆（新到舊）並註明總數 |
| 程序統計（4b） | 依程序名稱彙總（不分 PID）前 10 名：進入 Top N 的次數與比例、平均與最大 Working Set，依最大排序 |
| 預期樣本數 | 依 Application Log 的「監控開始」與停止紀錄：每個監控時段 ⌈時長 ÷ CSV 間隔⌉ ＋ 1（開始時一筆、每個間隔一筆、停止時補寫一筆；4a 原為 ⌊⌋＋1，4b 修正）；沒有停止紀錄時以時段內最後一筆資料為結束；程式沒有開啟的時間不算缺失 |
| 損毀資料 | 壞列（欄位數不對、時間／數值／狀態無法解析）略過並計數；空檔或標題列不符的檔整個略過；都列在資料品質。以共用讀取開啟，監控中也能產生報告；不修改原始檔 |
| HTML 安全 | 單一檔案、CSS 內嵌、不載入外部資源（Content-Security-Policy `default-src 'none'`）；所有資料與 Log 文字 HTML 編碼 |

## 影響

- Reporting（`net10.0`，只參考 Core）負責統計、彙總與 HTML；Application 的 `ReportService`／`ReportDataReader` 讀取與解析，檔案存取經 `IReportStore`（Infrastructure 的 `FileReportStore` 實作）。
- 讀取端的 CSV 欄位定義（`ReportCsvFile`）與寫入端（`CsvTables`）由 Infrastructure 測試比對，避免兩邊不一致。
- 記憶體：平均與最大串流累加；P95 需保留有效值（單精度），一年每 10 秒一筆約 12 MB／指標。
- Smoke Test 在 Windows CI 以 `report` 產生當天報告並檢查內容。
